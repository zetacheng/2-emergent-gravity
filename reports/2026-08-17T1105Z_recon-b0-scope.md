## 10. `A10` — the kill criteria

**Verbatim, `GATES.md:757-759`:**

**COULD EITHER BE MISTAKEN FOR A PHYSICAL RESULT? YES — the first, and
badly.**

**`−3` is the Proca value at the physical point `k=1`.** A degenerate pipeline
returning it for every `k` returns **the physically expected number** at the
point anyone would check first. **A run reporting only `k=1` would be
indistinguishable from success.** **What distinguishes them is the `k`-scan** —
which is why the gate's Scope says *"vary only `k`"*, and why
`betav_discriminating.py` exists to establish at the analytic layer that the
target is structure-dependent. **The `k`-dependence is the entire
discriminator, and a single-`k` run has none of it.**

**The second is less mistakable and not innocent.** A heavy-mass drift toward
`−5` is not a value anything predicts, so it would not read as success — **but
`reproduce_betav.py`'s docstring records this drift as a KNOWN feature of the
recovered pipeline, attributed to the longitudinal flat band.** **A new
pipeline reproducing it could therefore be read as faithfully reproducing the
historical behaviour rather than as carrying the same artifact.** The gate's
own wording is the guard: it calls the drift an artifact, not a signature.

**AND A THIRD FAILURE MODE THE GATE DOES NOT NAME, recorded because `A5` found
it.** **Six of the eleven scripts embed the analytic target or its formula.** A
reconstruction importing any of them into its measuring stage could recover the
target through the import rather than through the physics — **and neither kill
criterion would fire**, because the scan would track `−(k+2)` for the wrong
reason. **`GATES.md:415-418` already requires a blind harness for exactly this,
and `harness_compute.py` is built to that discipline.** This is a scope
requirement, not a new criterion, and it is reported rather than added.
