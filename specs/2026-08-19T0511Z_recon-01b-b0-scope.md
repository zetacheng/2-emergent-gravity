## 1. Objective

Answer two questions by measurement, so that a PI decision on `RECON-01b`'s
blind target rests on the current state of the repository rather than on
figures carried from earlier reports.

    Q1   What is the state of each of RECON-01b's ten components at
         968e726a?

    Q2   What does the axis-TT projection remove from the object a k-scan
         would examine, and where does CIRC-01's measured mixed sector fall
         relative to that object?

**Neither question asks whether `RECON-01b` should proceed, and neither asks
what should be done about the blind target.** Those are PI decisions and §12
excludes them.

## 1a. Non-objectives

This task does **not**:

1. decide whether the blind target and kill values are reusable,
   re-registered, or amended — the measurement informs that decision and does

2. run any part of `RECON-01b`, produce any `β_V` number, or execute a `k`-scan;
3. implement, repair, or port any component;
4. re-adjudicate `CIRC-01`'s verdict `DECOMP-UNAVAILABLE-AS-RECOVERED`;
5. modify any file under `scripts/`, including the frozen clean-room blobs;
6. merge anything into `main`, or move `main` at all;

## 2. Measurements

Every value is measured at `968e726a`. **No state, count, or classification is
carried from `derivations/P2-BETAV-RECON-01_scope-assessment.md`, from the
session handover, or from any report.** Those are prior observations against
earlier trees and are **not targets**.

    M1   For EACH of the ten components of RECON-01b, re-determine its
         existence state at 968e726a, using the four mutually exclusive states
         the prior assessment defines and the same applicability test — an
         implementation counts only if it is potentially applicable to the
         clean-room reconstruction.

         Record per component: the state as measured; the file and line
         evidence for that state; and, where an implementation exists but is
         not applicable, the stated reason.

         Record the four totals and their sum. Re-measure the totals from the
         per-component states; do not carry them from the prior assessment.

    M2   For each component whose measured state DIFFERS from the state
         recorded in the prior assessment, record the difference and its
         cause. If none differs, record that, with the comparison shown.

    M3   Read the axis-TT projection as it is defined in the repository —
         both its specification and any implementation — and record what it
         retains and what it discards, in the sector decomposition CIRC-01
         uses.

    M4   Read CIRC-01's q²-level decomposition and record each sector it
         reports together with that sector's measured magnitude, as stated.

    M5   Determine, from M3 and M4 together, whether each sector M4 reports
         falls inside or outside the object that survives the projection of
         M3. Record the determination per sector, with the evidence.

         **M5 limitation.** The determination is structural. If a sector
         cannot be classified without executing code that computes a `β_V`
         value, a `k`-scan, or any quantity over which the blind target
         ranges, record that sector as `INCONCLUSIVE` and **do not execute the
         computation**. `INCONCLUSIVE` is an allowed `M5` determination and
         satisfies `C4` for that sector. An `INCONCLUSIVE` sector is a
         completed measurement with a recorded reason, not a failure and not
         an abort.

    M6   Record whether the blind target and kill values for RECON-01b are
         currently frozen, where they are recorded, and by what mechanism —
         locations and text as read, not as remembered.

## 5. The two questions, stated without forecast

### 5.1 Q1 — component states

**This specification does not state what the states are, how many components
are in each state, or whether any state has changed.** It states only that
each of the ten is to be re-measured and the totals recomputed from the
per-component results.

One property of the prior assessment is worth carrying as a *method* note,
not as an answer: it recorded that some components classified without a usable
implementation nonetheless have code in the repository, the implementation
being ruled not potentially applicable for a stated reason. **The measurement
must therefore distinguish "no code exists" from "code exists and is not
applicable", and record the reason in the second case.** Whether either case
occurs at `968e726a` is what `M1` measures.

### 5.2 Q2 — what the projection removes

`CIRC-01` reports a sector decomposition at the `q²` level with a magnitude
for each sector. The axis-TT projection selects a sector.

**The question is structural: for each sector `CIRC-01` reports, does it
survive the projection or not?** A sector that does not survive is absent from
the object a `k`-scan would examine, whatever its magnitude.

**This specification does not state which sectors survive, does not state any
magnitude, and does not state whether a non-surviving sector matters.** `M3`
through `M5` measure the first; the magnitude is `M4`'s to read from
`CIRC-01`; whether it matters is a PI judgement excluded by §12.

## 6. Required content of the derivation artifact

1. `M1`'s per-component table, with evidence per row, and the four totals
   recomputed from the rows with the sum shown.
2. `M2`'s comparison against the prior assessment, in either direction —
   differences with causes, or the explicit statement that none differs, with
   the comparison shown either way.
3. `M3`, `M4` and `M5`, with `M5` per sector.
4. `M6`'s locations and text.
5. A statement of what the assessment does **not** establish, naming at
   minimum: that it produces no `β_V` value, that it makes no PI decision on
   the blind target, and that a count of components is not a measure of
   difficulty or duration.
6. Any question the measurement raised that it could not settle, recorded as
   open rather than resolved in prose.

**The artifact must not recommend a course of action on the blind target.**

    C2   The four totals are present and their sum equals the number of rows.

    C3   M2 is present in one of its two forms, with the comparison shown.
    C4   M3, M4 and M5 are present, and M5 has one determination per sector

## 8. Substring hazards

Any check performed by search must state its exclusions in the report.

    TT              matches tt_check, and matches inside unrelated words
    projection      does not match projector; both may be relevant and they
                    are not the same object
    transverse      appears in both the sector name and in prose about the

                    written alike; state which is meant at each use
    C5              this specification's criterion C5 and component 5 of the
                    inventory are different objects; the report must not use
                    the bare token for both

A check that cannot state its exclusions is performed by reading, and the
reading recorded.

## 9. Criterion satisfiability

No criterion requires the report to contain a term in order to locate it.

`C7` is a negative criterion and is satisfiable: it is established by reading
the artifact for a recommendation and for a numerical `β_V`, and PASSES on
their absence. It does not require the artifact to declare that it contains no
recommendation — §6 requires a statement of non-establishment, which is a
different thing and is checked by `C6`.

The `M5` limitation in §2 states an exclusion rather than a target: `M5` may
return `INCONCLUSIVE` per sector, `C4` accepts it, and an `INCONCLUSIVE` `M5`
is a completed measurement. It is not an abort condition and §3 does not list
it.
