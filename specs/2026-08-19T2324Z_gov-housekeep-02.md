## 6. MECHANISM — disposition of `INCONCLUSIVE` results

### 6.1 The problem this addresses

`PASS` and `FAIL` are self-closing. **`INCONCLUSIVE` creates an obligation
with no owner and no closing condition**, discharged only by someone
remembering it.

Not hypothetical here: `P2-RECON-01B-B0`'s re-measurement was executed,
verified, and never integrated; the landed baseline is still the earlier
assessment. No one objected — no one carried it.

**The deeper problem.** "Present evidence is insufficient to complete the
proof" is being treated as a terminus, when in research it is often the
starting point for "what exactly is still missing?" Those are different
epistemic states and the programme has not distinguished them.

`P2-RECON-PROJ-01`'s `Q1` is the case that surfaced it: a Ward identity and a
trace identity already in the manuscript, already yielding a conclusion of the
shape the test asks for, with a correspondence between two bases and possibly
a relation between two regimes missing — finite, explicit, separately
investigable. **That is not the same state as not knowing the answer.**

**The governance so far has been good at preventing false positives.** This
adds the other half: not letting a line stop permanently at `INCONCLUSIVE`
because the executor correctly declined to take the last step.

### 6.2 What is NOT changed

**The prohibition on promoting a result that fails a pre-registered test
stands unchanged.** A test returning `INCONCLUSIVE` because a required part
was unsatisfied must continue to return `INCONCLUSIVE`. Nothing here licenses
relaxing a criterion after seeing the evidence.

**The gap being closed is on the disposition side, not the verdict side.**

### 6.3 The mechanism, as ruled

Landed verbatim:

> An `INCONCLUSIVE` finding is not terminal when the assessment identifies a
> finite, explicit set of missing bridges whose establishment could change
> the result to a positive finding.

Every `INCONCLUSIVE` result carries one of two subclasses, assigned when the
result is recorded:

    INCONCLUSIVE — CONSTRUCTIVE GAP IDENTIFIED
        A candidate positive argument already exists, and what is missing is
        a finite, explicit, separately investigable set of bridges.

    INCONCLUSIVE — EVIDENCE INSUFFICIENT
        No clear next step is identified.

**Assigning a subclass is required, not optional.**

### 6.3a The required field

Every `INCONCLUSIVE` assessment answers, as a named field:

    Resolution path
        What is the minimum additional derivation, measurement,
        construction, or evidence that would be sufficient to RESOLVE this
        finding?

**The executor defines the path. The executor does not walk it.** Supplying
the missing bridge is theory construction and remains prohibited within a
verification task.

**The path is symmetric, and this is deliberate.** Resolving a finding may
upgrade it and may equally refute it. A field asking only what would make a
finding positive would bias the definition of the gap toward the answer
wanted — the failure mode this governance exists to prevent, arriving from
the other side. **A `Resolution path` naming only the confirming outcome is
incomplete.**

### 6.3b The workflow this enables

    verification
      -> INCONCLUSIVE with subclass and Resolution path
      -> constructive-gap extraction
      -> bounded derivation or measurement task
      -> re-verification

The bounded task is separate from the verification that identified the gap.
**Its outcome is not predetermined**: it may return a negative result, and
that is a completed task, not a failure of the mechanism.

### 6.4 The PI decision file

Created in `decisions/`. Part 1 records: what was decided — that
`INCONCLUSIVE` results carry a subclass per §6.3 and a `Resolution path` per
§6.3a, and that such a finding is not terminal when a finite explicit set of
missing bridges is identified; who and when; effect and scope, applying from
this landing forward; that the mechanism was proposed by the Researcher in a
different form, superseded by the PI's distinction, and approved as ruled;
that §6.2's prohibition is unchanged; and the evidence that motivated it,
naming the unintegrated re-measurement.

Part 2 carries the review if supplied, `REVIEW PENDING` if not — which under
§5.1 does not delay effect.

### 6.5 Retrospective application

**Prospective.** Existing `INCONCLUSIVE` records are not retroactively
subclassified by this task. The audit that classifies them is separate, and
**its result is not assumed here**: how many existing records carry a
constructive gap is unmeasured and is not estimated.

## 7. RULING 7 — corrected locators, and a departure from the Reviewer's recommendation

### 7.1 What the Reviewer recommended

That `W-2` be applied as an in-place edit to the landed specification, with a
new maintenance review binding for the corrected bytes and the original
binding preserved in provenance; and that `W-1` be handled by a clarification
note rather than an edit.

### 7.2 What this specification does instead, and why

**Neither correction is applied as an edit to any landed specification.**
Both are recorded as errata.

Three reasons, stated so the departure can be judged:

1. **A landed specification's bytes are the evidence of what was executed and
   what was reviewed.** Editing them produces a document that no execution
   ever ran against and no review ever approved. For a semantic clarification
   that trade may be worth making; for an article it is not.
2. **Editing a review-bound landed record pre-empts ruling 2's open
   question**, which `M6` shows applies to `specs/` and not only to
   `CONVENTIONS.md`. Ruling 2 says do not settle it. Editing one bound record
   settles it by practice.
3. **An errata record delivers the same benefit to a reader at no provenance
   cost.** A reader meeting either passage finds the correction; nothing that
   was executed is retouched.

**Cost, stated honestly:** a reader who never consults the errata record sees
the uncorrected text. That is the price of not rewriting evidence, and it is
the smaller price for corrections of this size.

### 7.3 The errata record

One entry in the register `M4` selects, recording for each of `W-1` and `W-2`:
the true file and line span as measured by `M3`; the exact current text; the
correction; that the landed bytes are deliberately unmodified; and, for `W-1`,
that the narrowing was already recorded beside the passage in that
specification's review artifact.

**No `specs/` file is modified.** `A6` fires if one would be.

### 7.4 Returned to the PI

If the PI directs that either correction be applied in place, that is a
separate task, and it needs ruling 2's question answered first — or an
explicit PI ruling that this instance is exempt.
